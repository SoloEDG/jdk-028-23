# LOGIC LAB

## 安装与本地启动

需要 Node.js 22 或更新版本。

```sh
npm install
npm run dev
```

打开终端显示的地址。类型检查、构建与测试：

```sh
npm run typecheck
npm run build
npm test
```

## Docker 启动

```sh
docker compose up --build
```

浏览器打开 http://localhost:8028 。

## 多标签协同与冲突恢复

实验存档已从单槽位升级为「正式存档 + 每标签分支 + 冲突会话」三层模型，
全部基于浏览器 localStorage 与 `storage` 事件实现，无需后端。

- **正式存档（head）**：带单调递增的 `revision`，保存成功才会替换。
- **标签分支（draft）**：每个标签独立自动保存，互不覆盖；标签关闭后仍可通过
  工具栏「分支恢复」找回未提交改动。
- **共同版本三方合并**：保存时若远端已有新版本，会以分支起点为共同祖先，
  生成 base / 本地 / 远端三方差异，并分四类展示——
  位置改动、输入值改动、接线改动、元件增删与命名。
- **逐项解决**：每个条目可选择「采用本地」「采用远端」，接线与位置还支持
  「手动重接 / 手动坐标」。不同元件上的改动不会被当作无冲突，合并结果会统一
  校验反馈环、双驱动、悬空线、目标输入名称重复及数量上限。
- **预览与提交门槛**：右侧实时预览完整结果的信号传播与目标真值表检测；
  仍不合法（存在阻断错误）的合并不允许替换正式存档。
- **解决期间远端再次保存**：当前解决进度全部保留，仅把远端再变的条目标记为
  「待重核」，用横幅提示而非弹窗；重核完成前禁止提交。
- **冲突副本**：可导出独立的冲突副本文件，在任意标签导入后继续解决。
- **旧版无损升级**：首次打开若检测到 v1 单槽位存档，会原样备份并迁移为 r1，
  原键与备份键都保留，不丢内容。
